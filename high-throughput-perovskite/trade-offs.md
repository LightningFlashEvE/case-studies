# 技术选型：设备控制上位机

选型依据来自项目描述和模块划分。未进行新的横向性能测试，不给出未经测量的吞吐量或响应时间。

| 决策 | 候选方向 | 采用方向与主要取舍 |
|---|---|---|
| 桌面交互 | Web 界面、原生平台界面、Qt Widgets | C++ / Qt Widgets 便于集成桌面控件和通信模块；需要维护原生工具链与依赖 |
| 任务执行 | 同步阻塞、事件驱动队列 | 事件驱动加异步队列便于保持界面响应；状态、超时和迟到反馈更需要清晰管理 |
| 设备接入 | 单一协议、按设备适配 | 网络与串行通信分层接入；避免让设备协议细节侵入展示层 |
| 任务保存 | 临时内存、持久化记录 | 项目说明采用数据库保存任务及配方；数据库状态不能替代重启后的现场核对 |
| 流程展示 | 文本日志、工位和步骤视图 | 工位视图配合步骤状态有助于定位当前进度；动画应跟随状态而非充当执行依据 |
| 异常恢复 | 自动重放、核验后恢复 | 设备动作可能不可重复；恢复设计应区分查询、可重试操作与需要人工核验的步骤 |

高通量需要通过完整任务链路评估，而不是只测单条通信往返。实际验收还应记录设备等待、称量稳定、异常处理和人工介入耗时。
