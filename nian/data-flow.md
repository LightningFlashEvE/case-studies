# 数据流：从录音到回答，再到清理

## 正向处理

```mermaid
flowchart LR
    A[音频片段] --> B[稳定转写]
    B --> C[来源关联与修订]
    C --> D[提炼记忆]
    D --> E[每日笔记]
    D --> F[派生检索索引]
    E --> G[问询读取]
    F --> G
    G --> H[需要细节时核对原文]
    H --> I[回答与出处]
```

虚构示例：先记录“下周三交材料”，后记录“改为下周五”。系统需要识别两句是否谈论同一事项，保留变更依据，并区分计划与实际完成状态。

## 问询的读取深度

```mermaid
flowchart TD
    Q[用户提问] --> P{需要什么证据}
    P -->|近期概览| N[先读已有笔记]
    P -->|具体事项| S[定向检索]
    P -->|精确数量| C[本机统计]
    N --> D{内容足够吗}
    D -->|是| A[带出处回答]
    D -->|否| S
    S --> R[读取相关原文并核验]
    R --> A
    C --> A
```

“没有检索到”不能自动改写成“没有发生”。答复应区分资料不存在、尚未处理、范围不足和查询失败。

## 清理与一致性

```mermaid
flowchart TD
    A[处理结束的录音] --> B{是否明确可清理}
    B -->|未完成或失败| C[保留并等待处理]
    B -->|有效信息| D[继续保留]
    B -->|成功空转写或明确无信息价值| E[检查人工修改与引用保护]
    E --> F[清理允许删除的音频与转写]
    F --> G[同步处理索引与派生内容]
    G --> H[核验持久化结果]
```

没有生成总结或笔记本身不是删除依据。混合录音需要保留有效片段与必要上下文。清理结果需要检查文件和索引，不能仅凭界面条目消失就判定完成。
